# AGENTS.md

Development rules for the `yimo-pi-kit` repository. Pi loads this file as project context — follow it when working in this repo. It exists to keep the package publishable: every release gate (`npm run check`) enforces the rules below.

## What this repository is

A portable Pi coding-agent profile package: extensions, subagents, skills, prompts, themes, pinned MCP templates, and an optional local code-review graph integration. Distributed as an npm package (`yimo-pi-kit`) and Git tags. No credentials, sessions, caches, or machine-specific state ever belong here.

## Hard rules (enforced by `npm run check`, never violate)

- **No secrets or private state.** Never commit `auth.json`, API keys, OAuth tokens, passwords, cookies, local trust decisions, Pi session JSONL, model stores, MCP caches, `.code-review-graph` data, backups, or `state/` directories.
- **No personal or private paths.** No absolute paths pointing at the author's home directory, no private gateway addresses, no private provider names, no real API-key material. Use `~`, environment variables, or relative paths.
- **No symlinks** (not publishable) and no Python cache artifacts (`__pycache__`, `*.pyc`).
- **No lifecycle scripts that install external software.** All setup is explicit via `scripts/cli.mjs` subcommands; the package must install without side effects.
- **Never commit runtime state** generated by the kit itself (downloaded skill sources, graph databases, generated reports).

## Structure

- `extensions/<name>/index.ts` — one extension per directory, default-exporting a factory `(pi: ExtensionAPI, ctx: ExtensionContext)`. Single-file extensions live at `extensions/<name>.ts`.
- `skills/<name>/SKILL.md` — skill with YAML frontmatter (`name`, `description`, `license`).
- `agents/*.md` — subagent definitions with YAML frontmatter (`name`, `description`, optional `skills`/`mcpConfig`).
- `prompts/*.md` — prompt templates. `themes/*.json` — themes. `mcp/*.json` — pinned MCP profiles.
- `examples/` — sanitized example configs (never real credentials). `scripts/` — CLI and release checks. `docs/` — user documentation.

## Manifest registration (critical)

Every bundled resource must be registered in `package.json` under the `pi` field (`extensions`, `skills`, `prompts`, `themes`). `scripts/check.mjs` runs a reverse validation: any resource present on disk but missing from the manifest fails the build. The token-speed extension shipped unreachable for three releases (0.4.2/0.4.3/0.4.5) because it was never added to `pi.extensions` — when adding **or removing** a resource, update the manifest in the same change.

## SKILL.md / agent frontmatter traps

- `name` and `description` are required.
- A plain-scalar description must not contain `Key: value` (colon + space) — YAML parses it as a nested mapping and the whole skill silently fails to load. Quote such descriptions instead: `description: "..."`. The `code-review-graph-usage` skill hit exactly this bug.
- Keep descriptions single-line; put trigger words after a short factual sentence.

## Extensions

- Import types from `@earendil-works/pi-coding-agent` (and `@earendil-works/pi-tui` for UI work).
- Default-export the factory function; use `pi.on(...)` for events, `pi.registerTool(...)` for tools, `pi.addCommand(...)` for commands.
- Prefer `ctx.signal` for abortable async work so Esc/cancellation propagates.
- Chinese comments in code are fine; the whole file must typecheck (`npm run typecheck`).

## Compatibility

- Node `>=22.19.0`; Pi `>=0.84.0` (see `engines` and `peerDependencies`).
- Changes to agent behavior, tool permissions, automatic side effects, resource names, MCP servers, or required Pi APIs are release-significant — bump the minor version, not the patch.

## Commands

- `npm run check` — typecheck + publishability validation (symlinks, private paths, secret patterns, manifest integrity, frontmatter parsing). Must be green before committing anything that touches packaged resources.
- `npm run audit:prod` and `npm pack --dry-run` — release gates; inspect the tarball file list.
- `npm run doctor` — local kit diagnostics.

## Release process (see docs/release.md)

1. Bump the version in `package.json` and the README "Status" line (docs/release.md templates too when they reference the current version).
2. `npm run check` green, then test in isolation: fresh `PI_CODING_AGENT_DIR`, `pi install <repo>`, start pi under a pseudo-TTY, and verify startup shows no extension errors and new resources actually load.
3. `git tag -s vX.Y.Z` → push → CI creates the GitHub Release.
4. `npm publish`, then consumers install with `pi install npm:yimo-pi-kit@X.Y.Z`. Versioned refs are pinned — `pi update` does not advance them; upgrades must install the new version explicitly.

## Style and history

- User-facing docs (README, docs/, SECURITY.md) are English; code comments may be Chinese.
- Keep `main` history linear; title release commits `Release yimo-pi-kit X.Y.Z`.
- Third-party skills are vendored via `scripts/skill-sources.json` pinned to full commits — never edit their contents in-tree. To add one, update the manifest, `THIRD_PARTY_NOTICES.md`, and the license review instead.
